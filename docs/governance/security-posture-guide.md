# Workspace Governance Security Posture Interpretation Guide

## Metrics Explanation

### 1. Security Score
A numerical value (0-100) representing the workspace's overall compliance level. Derived from policy drift presence, expired role counts, and access review status.

### 2. Security Grade
A letter representation (A-F) mapping directly to the Security Score range (e.g. 90+ is A, <60 is F).

### 3. Privileged Roles Count
Number of active users holding administrative permissions (`GOVERNANCE_OWNER`, `POLICY_ADMIN`, `EXCEPTION_APPROVER`).

### 4. Expired Roles Count
Count of roles whose expiration dates are in the past but have not yet been manually deactivated or cleaned up.

### 5. Inactive Roles Count
Count of roles that are explicitly flagged as inactive (`is_active = False`) and thus cannot execute actions.

### 6. Stale Roles Count
Count of role assignments that have not been used/logged into for over 90 days.

### 7. Pending Reviews
Number of open Access Review cycles requiring administrator evaluation.

### 8. High/Critical Findings
Active alerts or policy exceptions that present elevated risk (e.g. permissive presets on critical repositories).

### 9. Permission Denials
Count of blocked access attempts recorded in audit logs.

### 10. Self-Approval Blocks
Log of exceptions where a requesting user attempted to approve their own request and was blocked.

### 11. Bulk Partial Failures
Number of individual item failures during bulk actions (e.g. lockouts during cleanup).

### 12. Top Recommendations
List of prioritized remediation actions generated by the analytics engine to improve the score.

---

## Required Disclaimer
> [!IMPORTANT]
> **Advisory Nature of Security Posture Metrics**
> * **Security posture is advisory only**: The metrics and score serve to inform administrators of risk and do not represent hard runtime gates.
> * **No impact on quality gates**: A low security score or grade does not fail or affect CI/CD quality gate evaluations.
> * **No impact on release decisions**: Release readiness decisions are based on test and validation coverage, not security posture metrics.
> * **No impact on recommendation health**: The readiness state of recommendations is independent of the workspace security posture.
> * **No impact on GitHub status**: VeriScope commit status checks published to GitHub remain unaffected by security score adjustments.
